`source_line` is the one-based line in the corresponding raw log. For an interleaved NCCL row, it identifies the row prefix; the numeric tail can appear later. No missing sizes are filled with invented values. Raw precision is retained in the numeric CSV values, with trailing zeroes normalized.

At 256 MiB, out-of-place elapsed times are 1,358,372 µs (RDMA) and 471,638 µs (Socket), a ratio of about 2.88. Printed busbw values are rounded to two decimals. The tool's **scan-average** busbw is 0.0765298 GB/s for RDMA and 0.204685 GB/s for Socket (ratio about 2.67). That average mixes message sizes and both buffer modes; it is not a large-message plateau or a mean across independent trials.

## Failed and incomplete measurements

The 4-QP run prints a 1 MiB row immediately followed by `Completion with error at client` and `Failed status 5`. That row remains in the CSV with `valid=false`; plots exclude it. Larger sizes were not completed. Status 5 is a work-request flush error according to [rdma-core v50.0](https://github.com/linux-rdma/rdma-core/blob/v50.0/libibverbs/verbs.h#L461-L474), and does not identify the initiating cause. Earlier completed sizes are reported as partial results of a failed scan, without implying repeatability.

The CPU session has no archived duration-mode bandwidth output or timestamps. Aggregate `top` percentages cannot be assigned exclusively to rxe or a particular user process; nice time and steal time are present. The [CPU figure](figures/cpu_samples.png) uses sample order independently for each node and omits the first `top` sample, which is not a normal interval sample. It does not align the nodes in time.
